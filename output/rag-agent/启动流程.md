# rag-agent 启动流程

> 从零到发出第一个真实问题并收到回答，完整步骤。
> 每步按顺序执行，不要跳步。

---

## 前置确认清单

- [ ] Python >= 3.11（`python --version`）
- [ ] uv 已安装（`uv --version`，没有则 `pip install uv`）
- [ ] Docker Desktop 已启动（`docker ps` 无报错）
- [ ] `.env` 文件已配置（参考 `.env.example`）
- [ ] BGE-M3 模型已下载到本地（`EMBEDDING_MODEL_PATH` 指向的路径存在）
- [ ] BGE Reranker 模型已下载到本地（`RERANKER_MODEL_PATH` 指向的路径存在）

---

## S1 · 启动基础设施

**目标**：启动 Milvus、MongoDB、MinIO 三个服务
**为什么要先做这步**：import server 和 query server 启动时就会尝试连接它们，基础设施没起来会立刻报错

```bash
docker-compose up -d
```

**预期看到**：
```
[+] Running 6/6
 ✔ Container rag-agent-milvus-etcd-1    Started
 ✔ Container rag-agent-milvus-minio-1   Started
 ✔ Container rag-agent-milvus-1         Started
 ✔ Container rag-agent-mongodb-1        Started
 ✔ Container rag-agent-minio-1          Started
```

等待约 20-30 秒让 Milvus 完全就绪，然后验证：

```bash
curl http://localhost:9091/healthz
```

预期返回：`{"status":"ok"}`

**常见报错**：

| 报错关键词 | 原因 | 修复命令 |
|-----------|------|---------|
| `port is already allocated` | 端口冲突 | 修改 docker-compose.yml 左侧端口号 |
| `Cannot connect to the Docker daemon` | Docker 没启动 | 打开 Docker Desktop |
| Milvus 反复 `Exit 1` | etcd 还没 ready | `docker-compose restart milvus` |

---

## S2 · 安装 Python 依赖

**目标**：安装 pyproject.toml 中定义的所有依赖
**为什么要先做这步**：首次运行必须先安装，后续不需要重复执行

```bash
uv sync
```

**预期看到**：
```
Resolved X packages in Xs
Prepared X packages in Xs
Installed X packages in Xs
```

**常见报错**：

| 报错关键词 | 原因 | 修复命令 |
|-----------|------|---------|
| `Network` / `timeout` | 网络问题 | 换镜像源或关 VPN 代理后重试 |
| `torch` 安装极慢 | PyTorch 包体积大 | 耐心等待，约 5-10 分钟 |

---

## S3 · 启动导入服务

**目标**：启动 import server，监听 8001 端口，用于文件上传和向量化入库
**为什么要先做这步**：必须先导入文档，查询才有内容

新开一个终端窗口：

```bash
uv run uvicorn app.import_process.api.import_server:app --port 8001 --reload
```

**预期看到**：
```
INFO:     Application startup complete.
INFO:     Uvicorn running on http://0.0.0.0:8001
```

> 首次加载 BGE-M3 模型需要约 1-3 分钟，看到 `Application startup complete` 才算就绪。

**常见报错**：

| 报错关键词 | 原因 | 修复命令 |
|-----------|------|---------|
| `ConnectionRefusedError` (Milvus) | Milvus 没启动或还没 ready | 确认 S1 完成且 healthz 返回 ok |
| `FileNotFoundError` (模型路径) | `.env` 里路径配错 | 检查 `EMBEDDING_MODEL_PATH` |
| `ImportError` | 依赖没装 | 重新 `uv sync` |

---

## S4 · 导入测试文档

**目标**：上传一个 PDF 文件到系统，触发向量化入库
**为什么要先做这步**：没有文档，查询会返回"没有找到相关信息"

打开浏览器，访问：

```
http://localhost:8001/import
```

选择一个小 PDF（10 页以内），点击上传。

或用 curl：

```bash
curl -X POST http://localhost:8001/upload \
  -F "files=@/path/to/test.pdf"
```

**预期看到**：返回包含 `task_id` 的 JSON，如 `{"task_ids": ["abc123"]}`

等待 30-60 秒（BGE-M3 向量化需要时间）。

```bash
curl http://localhost:8001/status/abc123
```

**预期看到**：最终 `status` 变为 `completed`（如果 T2.1 已完成）或 `pending`（T2.1 未完成时也正常，文档实际上已在处理）

**常见报错**：

| 报错关键词 | 原因 | 修复命令 |
|-----------|------|---------|
| `MineRU` 相关错误 | API Key 没配 | 检查 `.env` 中的 MineRU 配置 |
| `ConnectionRefusedError` (MinIO) | MinIO 容器没启动 | `docker-compose up -d minio` |

---

## S5 · 启动查询服务

**目标**：启动 query server，监听 8000 端口
**为什么要先做这步**：导入完成后需要 query server 才能提问

新开一个终端窗口：

```bash
uv run uvicorn app.query_process.api.query_server:app --port 8000 --reload
```

**预期看到**：
```
INFO:     Application startup complete.
INFO:     Uvicorn running on http://0.0.0.0:8000
```

**常见报错**：

| 报错关键词 | 原因 | 修复命令 |
|-----------|------|---------|
| `ConnectionRefusedError` (Milvus) | Milvus 没启动 | 确认 S1 完成 |
| `ConnectionRefusedError` (MongoDB) | MongoDB 没启动 | `docker-compose up -d mongodb` |

---

## S6 · 发起第一个查询

**目标**：通过前端或 API 发一个问题，验证系统端到端工作
**这是跑通的定义**

打开浏览器，访问：

```
http://localhost:8000/chat.html
```

或用 curl：

```bash
curl -X POST http://localhost:8000/query \
  -H "Content-Type: application/json" \
  -d '{"question": "你刚才上传的文档讲了什么？", "stream": false}'
```

**预期看到**：包含文档内容的回答（不是"没有找到相关信息"）

**常见报错**：

| 报错关键词 | 原因 | 修复命令 |
|-----------|------|---------|
| 回答"没有找到相关信息" | 文档还没入库，或查询时 item_name 对不上 | 等待几秒后重试；或检查 Milvus 里是否有数据 |
| SSE 连接断开 | DashScope API Key 无效 | 检查 `.env` 中的 `LLM_API_KEY` |

---

## 🎯 跑通定义

完成以下验证视为跑通：

1. `docker-compose ps` 显示所有容器 `Up`
2. 两个 server 都显示 `Application startup complete`
3. 上传一个 PDF 后，查询能返回该 PDF 中的内容

---

## 停止服务

终端里的 server：按 `Ctrl+C`

停止 Docker 容器（保留数据）：
```bash
docker-compose stop
```

删除容器（保留数据卷，数据不丢）：
```bash
docker-compose down
```

删除容器和数据（慎用）：
```bash
docker-compose down -v
```
